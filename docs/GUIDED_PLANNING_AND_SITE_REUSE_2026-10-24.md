# Guided planning and reusable site requirements

Agreement creation now has one header action group instead of duplicate page and form toolbars. Save draft and Import agreement are available while required details are incomplete. Save agreement appears after the client, agreement name, scope, dates, pricing and crew requirements are valid. A completed draft is activated by Save agreement. An incomplete draft needs a client, name and valid dates; empty scope and crew remain unfinished when it is reopened.

The shared step component presents a numbered timeline, a current-step label, Previous and Next controls, and field guidance when Next cannot continue. New agreements cannot skip an incomplete earlier step. Going back retains the current form. The final step keeps Previous and the header save choices. Deletion remains available from the list and in the relevant record section, outside the save header. Mobile steps keep their accessible labels and emphasize the current step without widening the page.

Event creation uses Event details and Review and create. The preview shows the agreement's sites and crew before creation. Saved plans use Event information, Venues and crew, Transport and equipment, and Event timeline. Save event plan and Import event plan stay in the header. Agreement changes, worker assignment, pay, resource booking and billing actions appear in their relevant sections. Next saves event notes and budget; crew and booking actions retain their existing immediate saves. Assignment and financial-history protections are unchanged.

Selecting a previous client site immediately clears its stale required-field error. Site validation is inline and does not leave a second missing-values dialog behind. A copy reuses the site name, crew categories, counts, client prices and vehicle requirements. It assigns the **new agreement's start and end dates** to these editable requirements. Old dates, address fields, assigned workers, wage choices and booked vehicles are not copied. A seven-day previous plan can therefore be reused for a one-day agreement. Client/company access checks remain in the server API, and copying requirements does not create allocations or reservations.

The update also normalizes empty rich-text scope for draft saving and returns it as empty when reopening the draft. Success notices are delivered after record navigation finishes. Step listeners are removed when an editor is rebuilt; readiness checks do not mark untouched fields or issue network requests. No polling, new client-data cache, schema migration or change to existing financial records is introduced.
