# Draft flow and working-site loading repairs

The agreement editor called a new daily-billing component while an older cached Desk include list could omit that component. The missing draft script also left the List View selector visible. The update orders both dependencies before the editor, explicitly recovers missing dependencies before rendering, and applies the customer-list class from the shared layout. The native on-demand loader requires plain asset paths and supplies its own cache version. All changed includes use `20261024-draft-flow-4`; working and demo caches were refreshed.

Agreement and event creation now use partial drafts without creating incomplete client or financial records. One autosave session debounces changes, coalesces requests, flushes on tab hiding and keeps bounded, user/company-specific recovery data. Completed agreements create one event draft and offer event details or client signature as the next action. Event creation can be kept as Draft, created now or scheduled. The native scheduler handles at most 25 due drafts per minute, with locking, permissions, entitlement checks and visible failures. Customer lists omit List View; useful search and sorting remain.

Agreements show crew requirements followed by vehicle requirements. Actual vehicle and inventory allocations belong to events. Crew availability appears above the fields and shortages are associated with the crew-count input. Daily billing milestones group approved, unbilled attendance periods; they do not generate fixed-price revenue. Generated invoice references cannot be forged or removed through editing. Deleting an unused invoice releases its sources and checkpoint reference. Signed documents describe agreed vehicle requirements rather than internal equipment bookings.
